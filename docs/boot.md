# boot.md 系统启动流程规范（x86‑64）

> 
> 前提说明
> 
> 
> 1. x86‑64 平台，Ring1/Ring2 全程闲置，仅使用 Ring0 / Ring3。
> 2. 整个启动流程分水岭：**全局内核对象管理器初始化完成**；在此之前是裸内核阶段，没有对象、没有条目、没有 ACL。
> 3. 依赖：`os.md`、`acl.md`、`memory.md`、`ipc.md`、`process.md`、`fs.md`。
> 4. 内核分为：常驻最小基座 + 可加载内核模块；部分硬件、协议栈、VFS 功能以模块形式动态加载。

## 术语

- bootloader：引导程序（UEFI‑boot / GRUB 等），负责把内核镜像加载到物理内存。
- 早期内核：尚未初始化对象管理器，只有物理内存管理、页表、中断、PCI 枚举等底层基础组件。
- 内核对象管理器：系统根基，初始化完毕之后，才可以创建各类内核对象。
- init 进程：系统第一个用户态进程，PID=1，负责拉起整个用户空间环境。

## 1 完整启动阶段划分

系统从开机到进入桌面的完整顺序为：**引导程序 → 启动文件 → 微内核 → 内核扩展（混合内核） → 用户态主程序 → 常驻前台程序 → 图形环境 → 登录界面 → Linux 兼容层 → 自启动应用**。

1. **引导程序**：加载**启动文件**进内存，移交控制权（对应阶段 1‑2）。
2. **启动文件**：启动**微内核**；微内核加载**内核扩展文件**（扩展部分），构成**混合内核**（对应阶段 3‑5）。
3. **用户态主程序**：微内核通知**用户态主程序**（init），主程序**打开启动常驻前台程序并管理**——服务管理机、服务运行容器、触发任务器等（对应阶段 6）。
4. **命令行环境**：init 拉起命令行环境（`cmd.md`），提供基础操作与排障入口。
5. **图形环境**：启动窗口管理器、图形合成器与桌面（`ui.md`）。
6. **登录界面**：由登录与验证组件的登录程序（`login_app`，见 `auth.md`）显示登录界面，收集凭据并完成验证（`auth_svc`）；会话由 `session.md` 建立。
7. **Linux 兼容层**：初始化 Linux 兼容层，可运行 Linux 应用（`Linux.md`）。
8. **自启动应用**：登录后按自启动配置拉起自启动应用（`service.md` / `pkg.md`）。

### 阶段 1：固件（UEFI / BIOS）

1. 硬件基础初始化，内存检测。
2. 寻找磁盘上的引导程序，将 bootloader 加载进内存，移交 CPU 控制权。

### 阶段 2：Bootloader 引导程序

1. 解析磁盘分区，读取**启动文件**（内核启动映像：微内核 + 内核扩展文件清单）到物理内存。
2. 收集硬件信息：内存布局表、ACPI 表，传递给内核。
3. 切换 CPU 进入 x86‑64 长模式，跳转至内核入口，把信息块交给内核。
4. 启用**显卡文字模式**（80×25 文本控制台），显示引导提示。

### 阶段 3：微内核启动【裸微内核，无对象管理器】

> 
> 系统内核为**微内核**（microkernel）：仅包含最小核心——调度、物理内存、中断、IPC 基础；完整内核能力由**内核扩展文件**提供（阶段 5）。
> 本阶段**不存在任何内核对象，不能使用对象‑条目原语**。

1. 搭建临时页表，开启 MMU 分页，启用虚拟地址。
2. 初始化**物理内存管理器**（memory.md），管理整机 HPA 物理页。
3. 初始化异常向量表、APIC 中断控制器，设置基础异常与中断处理函数。
4. PCIe 总线枚举：遍历全部 PCI 设备，收集 DevID、BAR 物理 MMIO 地址、中断资源。
5. **显卡文字模式**控制台初始化（80×25 文本控制台 + 串口），用于开机提示与内核早期日志输出。
6. 按启动进度在文字模式显示**开机提示**（阶段文案：内存初始化 / 硬件枚举 / 模块加载 / 挂载根文件系统）。

### 阶段 4：内核基座初始化【分水岭：启动全局内核对象管理器】

> 
> 从此刻开始，对象‑条目、ACL、IPC 全部可用。

1. 初始化全局内核对象管理器，创建根对象命名空间。
2. 初始化 ACL 权限子系统 (`acl.md`)。
3. 初始化基础 IPC 事件子系统 (`ipc.md`)。
4. 根据 PCI 枚举结果，自动批量创建硬件对象：
   - `/object/hw/pci/<DevID>` 全部 PCI 硬件对象，状态标记为空闲，填入 MMIO、中断信息。
   - 网卡、显卡、输入设备、块设备硬件 IO 流对象完成创建。
5. 创建系统全局基础纯控制对象：
   - `/object/service_mgr` 服务管理器对象
   - `/object/vm` 虚拟机父对象
   - `/object/ipc/mq`、`/object/ipc/event` IPC 父对象
   - `/object/proc` 进程父对象
   - `/object/window` 窗口父对象
   - `/object/net/sock` 套接字父对象
6. 设置这些基础对象的默认 ACL 权限（例如`/object/service_mgr`：允许`CREATE_ENTRY`，拒绝`DELETE_ENTRY`）。

### 阶段 5：加载内核扩展文件（微内核 → 混合内核）

> 
> 微内核加载**内核扩展文件**（扩展部分）后，系统由纯微内核构成**混合内核**（hybrid kernel）：调度 / 内存 / IPC 核心仍驻留微内核态，文件系统、网络、服务等扩展以模块形式加载（Ring0）。
> 模块运行于 Ring0，模块 bug 会造成整机 panic。
> 按需加载内核扩展文件：

1. 块设备服务模块；磁盘文件系统模块。
2. VFS 虚拟文件系统适配层 (`fs.md`)。
3. `/system/dev` `/system/proc` `/system/sys` 虚拟节点后端模块。
4. 网络协议栈、网卡硬件服务模块。
5. 显卡、输入硬件内核服务模块。
6. VMX 虚拟化模块：仅当 CPU 支持 VMX 特性才加载。

> 
> 加载完成后执行挂载操作：
> 
> 
> 1. 挂载根磁盘文件系统；
> 2. 将对应 IO 流对象挂载到 VFS：`/system/dev`、`/system/proc`、`/system/sys`。

### 阶段 6：通知用户态主程序，启动并管理常驻前台程序

1. 内核对象管理器创建第一个进程对象：**用户态主程序**（init，PID=1）——参考 Windows 用户态主程序（wininit，负责启动并托管系统组件），按启动组拉起任务。
2. 加载用户态主程序镜像，创建主线程，进入可调度状态。
3. 用户态主程序运行在 Ring3，**打开启动常驻前台程序**并管理它们：
   1. **服务管理机**：统一管理全部服务（注册、启动、停止、崩溃重启，`service.md`）——参考 Windows 服务控制管理器（SCM，services.exe）；
   2. **服务运行容器**：承载服务运行——多个不冲突服务可**打包成一个进程**，每个服务一个线程，类似 Windows 服务主进程（svchost.exe）；
   3. **触发任务器**：按计划 / 条件触发任务（定时、开机、事件），对应 Windows 任务计划程序（Task Scheduler）。
4. **用户态第三方服务**（`hardware_svc.md`）：打开 `/object/service_mgr` 完成注册、硬件独占绑定、崩溃自动回收等机制不变。
5. 启动窗口管理器、图形合成器（`ui.md`）；图形环境就绪后合成器接管显示，退出显卡文字模式。
6. 启动网络管理服务及其它系统后台服务。

### 显卡文字模式（开机提示）

1. **模式**：80×25 文本控制台（引导 / 内核早期阶段，图形环境未就绪）；文字模式同时输出到串口。
2. **能力**：字符栅格显示、滚动、光标、前景 / 背景颜色（错误信息红色高亮）。
3. **提示内容**：按启动阶段显示——引导加载 → 启动文件 → 微内核 → 加载内核扩展 → 挂载根文件系统 → 启动用户态主程序（init）；每阶段一行，进度即时刷新。
4. **切换**：图形环境（合成器）就绪后切换到图形模式；文字模式期间合成器未运行，显示完全由内核控制。
5. **异常**：阶段失败时以文字模式红字显示错误信息，并进入紧急控制台 / 紧急 shell（见下节）。

## 2 异常、失败处理

1. **内核早期严重故障（阶段 1‑3）**
内存损坏、ACPI 错误、无法找到内核镜像。**显卡文字模式红字显示错误**，直接进入内核紧急控制台，**不拉起任何用户空间**。
2. **找不到根文件系统**
内核进入紧急 shell，无法执行到拉起 init。
3. **init 进程崩溃 / 异常终止**
内核检测 PID=1 消亡，触发系统紧急策略：可选择重启 init 进程，或者系统停机。

> 
> 其它普通进程崩溃由进程子系统自动回收，不会影响整机。

## 3 关键时序约束要点

1. **PCI 硬件对象，在对象管理器初始化完成之后立刻批量生成**，不是用户态服务运行才创建。
2. 用户态服务进程由 init 负责拉起；**硬件对象早已存在，只是处于空闲未绑定状态**。
3. VFS 的内存虚拟节点，依赖 IO 流对象，因此必须在对象管理器、硬件对象创建完毕之后，才能执行挂载。
4. VMX 模块只是内核可加载模块；即使不加载，系统其余全部功能可以正常运行。

## 4 和其余文档对接

1. **os.md**：对象管理器是内核基座的核心组件，是裸内核与完整系统的分水岭。
2. **acl.md**：全局基础对象在基座阶段设置默认 ACL 权限。
3. **memory.md**：物理内存管理器在内核早期裸内核阶段完成初始化。
4. **hardware_svc.md**：PCI 硬件对象启动阶段批量生成；用户态第三方服务后续注册、绑定硬件。
5. **process.md**：init 是内核创建的第一条进程对象；后续所有用户进程由 init 或者用户态进程派生。
6. **fs.md**：根磁盘挂载、VFS 对象挂载，发生在内核模块加载阶段。
7. **ipc.md**：IPC 子系统随对象管理器一起初始化。
8. **ui.md**：显卡硬件对象内核阶段创建；窗口管理器、合成器由 init 在用户态拉起；图形环境就绪后退出显卡文字模式。
9. **net.md**：网卡硬件对象内核阶段创建；网络管理服务由 init 用户态启动。
10. **vm.md**：VMX 模块按需加载；虚拟机对象全部由**用户态管理程序**后续创建，内核启动不会预先创建虚拟机。
11. **objmgr.md**：基座阶段启动全局内核对象管理器，创建根命名空间与全局基础对象。
12. **cmd.md**：init 拉起终端等命令程序；命令执行对象在基座阶段创建。
13. **external_dev.md**：基座阶段枚举 I/O 控制器；外部设备经设备对象接入系统。
14. **audio.md**：基座阶段加载声卡服务，创建音频设备对象；init 拉起音频服务。
15. **power.md**：电源/休眠由用户态守护进程管理；恢复启动路径与正常启动路径分离。
16. **service.md**：用户态主程序（init）打开启动服务管理机、服务运行容器、触发任务器并管理；打包容器承载多个不冲突服务同进程运行（每服务一线程）。
17. **kernel.md**：内核主镜像在引导阶段加载；可加载内核模块在阶段 5 动态加载。
18. **devmgr.md**：init 拉起设备管理器，接管设备发现与服务匹配编排。
19. **asm.md**：引导程序与内核镜像的汇编构建依赖汇编工具链。
20. **map.md**：init 拉起定位服务与地图应用（用户态服务/应用）。21. **install.md**：安装完成后重启进入开机流程；首次配置见安装器（install.md）。
22. **session.md**：开机流程"登录界面"步骤由会话子系统（session.md）承接。
23. **rtc.md**：引导阶段从 RTC 初始化系统时间（rtc.md）。
24. **secure_island.md**：引导链完整性度量写入 PCR，由安全岛（secure_island.md）校验。
25. **trigger_task.md**：用户态主程序（init）打开启动触发任务器（常驻前台程序之一），按计划 / 条件触发任务。
26. **auth.md**：登录界面阶段由 auth 的 `login_app` 承接，验证服务 `auth_svc.service` 以后台服务文件常驻。

## 5 设计取舍

1. 硬件对象在内核启动阶段一次性全部枚举创建，而不是动态按需创建；方便用户态服务直接发现全部硬件。
2. 把复杂的用户空间业务全部交给 init，内核只负责创建 init 进程对象，不做任何用户态业务逻辑。
3. VMX、网络协议栈等做成可加载模块，硬件不支持可以不加载，保持内核最小基座可用。
4. 严格区分「裸内核阶段」和「对象管理器就绪阶段」：裸内核不能调用任何对象‑条目原语，避免逻辑混乱。

## 6 启动流程 `.api` 契约文件（boot.api 全文）

启动流程对外接口统一由以下契约文件声明，文件存放于 `/system/api/boot.api`，由桥接层加载解析。**本文档内置本契约全文，后续接口增删改必须同步维护此处与契约文件两者一致。**

```text
# boot.api 系统启动流程对外接口契约
# API版本标识，主版本不兼容变更+1，次版本新增能力+1
version = 1.0
# 绑定目标子系统标识
target = boot
env = python
exec = /system/kernel/core
internal_loc = map + symbol + register
# 最低兼容系统内核版本
min_os_version = 1.0
# 全局默认ACL权限标签，单接口可单独覆写
global_acl = kernel
# 全局默认调用限流规则
global_limit = 100次/秒

# ---- 申请对外对象：object <对象目录> <对象名称>，空格分隔 ----
object /system/api/boot boot

# ---- 只读条目：无转换逻辑使用空大括号 {}，直接透传内部数据 ----
boot: phase { } /internal/boot/phase
boot: hw_enum { } /internal/boot/hw
boot: state { } /internal/boot/state

# ---- 可写控制条目：转换代码为Python，实现启动状态查询 ----
boot: get_phase {
    return self.get_phase()
} /internal/boot/phase_get

# ---- 对外可监听标准事件（保持原规范） ----
EVENT:
    boot_phase_changed(phase: str) ｜ /internal/event/boot_phase

# ---- 单接口独立ACL权限覆写（优先级高于global_acl） ----
ACL_OVERRIDE:
    get_phase: user_foreground
```

契约要点：

1. 启动阶段 / 硬件枚举 / 启动状态只读透传；启动流程本身由内核服务，不对外暴露修改。
2. 阶段变更事件供 init / 服务管理器与监控监听（阶段推进通知）。
3. `get_phase` 授权前台进程查询当前启动阶段。
