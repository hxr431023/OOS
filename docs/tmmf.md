# tmmf.md TMMF 资源文件（.tmmf）规范

> 
> 前提说明
> 
> 1. **TMMF** 为与 `.lerf`（`lerf.md`）同族的**应用层界面文本 / 弹窗资源文件格式**，后缀 `.tmmf`，魔数 `TMMF.`；本文档为 TMMF 笔记的正式化版本。
> 2. 完全基于 `os.md` 内核对象‑条目模型；文件读取受 `acl.md` 权限管控；哈希校验防篡改、防损坏（`security.md`）。
> 3. **条目不在此文档硬编码**：TMMF 资源对外条目的集合、命名、权限由 `tmmf.api` 契约文件声明，经 `.api` 桥接层加载；本文档只定义 `.tmmf` 文件格式与加载语义，契约全文见第 12 节。
> 4. 与 `.lerf` 的差异见第 10 节对照表；两者可并存使用（`.lerf` 通用语言资源、`.tmmf` 界面文本与弹窗资源）。
> 5. 依赖：`os.md`、`acl.md`、`fs.md`、`ui.md`、`font.md`、`lerf.md`、`security.md`、`.api.md`。

## 术语

| 术语 | 说明 |
| --- | --- |
| TMMF 资源文件 | 以 `.tmmf` 为后缀的资源文件，承载界面文本与弹窗布局 |
| 魔数 | 文件首行校验标识 `TMMF.`，前缀不符判为非法文件 |
| 程序标识符区 | 第 2–3 行，存放程序图标 / 界面文字 / 哈希，证明文件归属 |
| 占位符 | 文本内 `{0}` `{1}`… 运行时动态填充 |
| 标签组 / 内容组 | 有效数据行 `=` 左侧为标签组（程序内引用），右侧为内容组（显示文本） |

## 1 文件整体结构（逐行布局）

| 行 | 内容 | 说明 |
| --- | --- | --- |
| 第 1 行 | 魔数 + 文本编码 | `;` 分割：左=校验魔数 `TMMF.`，右=文本编码 |
| 第 2–3 行 | 程序标识符区 | 图标（`icon_xxx`）/ 界面文字 / 哈希字符串；固定占用两行 |
| 第 4 行 | 文件状态 | `0`=使用，`1`=不使用，`-1`=无效 |
| 后续行 | 数据行 / 注释行 | 有效数据行或 `#` 注释行，顺序不限 |
| 最后一行 | 文件末尾标记 | `…  …`（三个点 + 空格 + 三个点） |

## 2 第 1 行：魔数与编码

1. 读取首行，用 `;` 切割成两部分：
   - **左侧**：校验魔数 `TMMF.`，前缀不是 `TMMF.` 则判定文件非法；
   - **右侧**：文本编码（如 UTF-8）。

## 3 第 2–3 行：程序标识符区

1. 存放程序自身标识信息，用于证明"这是本程序的内容"，占用**第 2–3 行**（最多两行）：
   1. 图标标识：`icon_xxx`；
   2. 界面文字：窗口 / 按钮显示的本地化文本，支持 `{0}` 占位符；
   3. 哈希字符串：文件 MD5/SHA 校验哈希，校验文件程序完整性，防止篡改、损坏。
2. 三项内容均为**可选**，但**至少要有其中一项**。
3. 本区固定占用两行：若实际内容只占一行，第二行以空格填充。

## 4 第 4 行：文件状态

| 值 | 含义 |
| --- | --- |
| `0` | 使用（正在使用） |
| `1` | 不使用（保留放置） |
| `-1` | 无效（不能使用） |

## 5 注释规则

1. 行首为 `#` 的行直接忽略，不参与解析。

## 6 有效数据行

1. 语法：`<\>标签组=内容组</>`
   - 示例：`<\>界面文本1, 界面文本2…=界面文本1, 界面文本2…</>`
2. 规则：
   - `=` 左侧为**标签组**（程序内引用标识），右侧为**内容组**（界面显示文本）；
   - 组内多项（多个标签 / 多条文本）用 `,` 分隔；
   - 可合并一整行书写，也可拆分为多行书写；
   - 不同数据行之间用 `;` 分隔。
3. 占位符：文本内置 `{0}` `{1}`…，运行时动态填充。

## 7 弹窗布局（Dialog_）与分隔符

1. **弹窗整体**：`Dialog_` 扩展样式, 宽 `cy`, 高 `cx`, 控件总数, 字体字号；
2. **每个控件**（按钮 / 输入框）`Dialog_`：坐标 `xy`, 宽高, 控件类型, 文字 ID, 样式标志；
3. **分隔规则**：
   - **标签分隔**：同一标签组内的字段 / 界面文本项用**逗号** `,`（数据行内标签项与文本项、弹窗字段 `宽 cy`、`高 cx`、控件类型等、标识分类各项）；
   - **其它分隔**：标签组与标签组之间用**分号** `;`（不同数据行之间、弹窗整体与控件之间、控件与控件之间、首行魔数与编码之间）。

## 8 加载行为规范

1. 加载前校验魔数与哈希：魔数不符直接判非法；哈希不符判定文件损坏（防篡改）。
2. 状态为 `0`（使用）的文件才被加载；`-1`（无效）拒绝加载；`1`（不使用）不参与加载。
3. 程序运行时按标签组索引内容组文本，缺失标签回退到程序内建默认文本。
4. 弹窗资源按 `Dialog_` 定义生成窗口与控件，文字 ID 对应数据行标签。

## 9 与 `.lerf` 的差异对照

| 维度 | `.lerf`（lerf.md） | `.tmmf`（本文档） |
| --- | --- | --- |
| 魔数 | `LERF.` | `TMMF.` |
| 定位 | 通用语言资源文件 | 界面文本与弹窗资源文件 |
| 数据行语法 | `<\数字>界面文本…<数字ID/>`（数字 ID 标签） | `<\>标签组=内容组</>`（文本标签组 `=` 内容组） |
| 程序标识符 | 图标 / 字样 / 哈希 | 图标（`icon_xxx`）/ 界面文字 / 哈希 |
| 其余结构 | 逐行布局、状态、注释、Dialog_、分隔符、末尾标记一致 | 同左 |

## 10 与各子系统对接

1. **os.md**：`.tmmf` 为应用层资源格式，复用对象‑条目模型。
2. **acl.md**：资源文件读取受 ACL 管控。
3. **fs.md**：资源文件存放遵循 `/system/media` 或应用资源目录。
4. **ui.md**：界面文本、弹窗布局供 GUI 渲染使用。
5. **font.md**：程序标识符区的图标 / 界面文字与界面字体经字体规范加载。
6. **lerf.md**：同族格式，分隔符与结构约定互通。
7. **security.md**：哈希校验防篡改、防损坏。
8. **.api.md**：资源对外接口经 `tmmf.api` 契约与桥接层。
9. **Linux.md**：/system/linux/ 下的接口映射表（Linux / POSIX 接口名 → 本地接口）以 TMMF 数据行表达，等号左侧多个搜索词（逗号分隔）映射同一组结果（分号分隔）。

## 11 设计取舍

1. `.tmmf` 为纯文本格式，单文件承载界面文本与弹窗布局，便于分发与校验。
2. 标签组 / 内容组分离：程序按标签索引文本，替换语言不动程序逻辑。
3. 哈希校验前置，杜绝篡改 / 损坏文件进入加载流程。
4. 与 `.lerf` 并存不冲突：一个面向通用语言资源，一个面向界面文本 / 弹窗。

## 12 TMMF 资源 `.api` 契约文件（tmmf.api 全文）

TMMF 资源对外接口统一由以下契约文件声明，文件存放于 `/system/api/tmmf.api`，由桥接层加载解析。**本文档内置本契约全文，后续接口增删改必须同步维护此处与契约文件两者一致。**

```text
# tmmf.api TMMF 资源文件对外接口契约
# API版本标识，主版本不兼容变更+1，次版本新增能力+1
version = 1.0
# 绑定目标子系统标识
target = tmmf
env = python
exec = /system/media/fonts/font_loader
internal_loc = map + symbol + register
# 最低兼容系统内核版本
min_os_version = 1.0
# 全局默认ACL权限标签，单接口可单独覆写
global_acl = user_foreground
# 全局默认调用限流规则
global_limit = 100次/秒

# ---- 申请对外对象：object <对象目录> <对象名称>，空格分隔 ----
object /system/api/tmmf tmmf

# ---- 只读条目：无转换逻辑使用空大括号 {}，直接透传内部数据 ----
tmmf: loaded_res { } /internal/tmmf/res

# ---- 可写控制条目：转换代码为Python，实现资源加载与文本查询 ----
tmmf: load {
    self.load(path)
} /internal/tmmf/load
tmmf: get_text {
    return self.get_text(tag)
} /internal/tmmf/text
tmmf: dialog_get {
    return self.dialog_get(id)
} /internal/tmmf/dialog

# ---- 对外可监听标准事件 ----
EVENT:
    tmmf_loaded(path: str) ｜ /internal/event/tmmf_load
    tmmf_broken(path: str, reason: str) ｜ /internal/event/tmmf_broken

# ---- 单接口独立限流规则（覆写全局限流） ----
LIMIT_OVERRIDE:
    load: 50次/秒

# ---- 单接口独立ACL权限覆写（优先级高于global_acl） ----
ACL_OVERRIDE:
    get_text: user_foreground
```

契约要点：

1. 外部程序仅能访问 `/system/api/tmmf` 标准虚拟对象，禁止直连资源文件内部。
2. `load` 先做魔数与哈希校验，失败触发 `tmmf_broken` 事件。
3. `get_text` 按标签组索引内容组文本；`dialog_get` 返回弹窗布局定义。
4. 事件封装契约声明的标准参数；加载成功 / 损坏事件供应用监听。
